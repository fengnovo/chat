# Web 关键流程 E2E 设计

## 目标

为 Web 端关键用户流程建立可重复的浏览器端回归验证，覆盖本轮 React 状态/引用重构可能影响的登录、聊天、文件面板、灯箱、知识库、管理员和长期记忆页面。

## 范围

- 使用 Playwright Chromium 测试真实 Next.js 页面、路由和 DOM 交互。
- 通过 Playwright `page.route` 模拟 `/api/**` 响应，不启动数据库、Redis、知识服务、真实模型或第三方 OAuth。
- 复用一套认证与 API mock fixture，按测试覆盖未登录、普通已登录和管理员已登录状态。
- E2E 作为独立命令和 CI job 执行，不阻塞已有快速单元测试任务的本地开发循环。

## 覆盖流程

1. 登录页展示 OAuth 错误，并提交错误密码后展示登录失败。
2. 聊天首页加载会话，打开/关闭文件面板，切换历史会话并展示历史文件内容。
3. 文件面板目录切换、宽度拖拽和文件预览；消息中的图片打开灯箱并可关闭。
4. 知识库页面加载列表，进入文档管理、切片管理和检索页，切换知识库。
5. 管理员用户页加载用户列表；长期记忆页加载记忆列表并展示操作入口。

## 稳定性边界

- 每个测试自行注册 API route，不依赖外部网络或环境中的真实登录态。
- 不断言 CSS 像素和动画时长，只断言可访问名称、可见文本、URL、输入值和关键状态。
- 对需要真实 SSE、上传对象存储或模型输出的流程保留现有单元/集成测试，不在本轮伪造完整模型流。
- CI 安装 Chromium 浏览器并运行 `pnpm --filter web e2e`；失败保留 Playwright HTML report 和 trace。
