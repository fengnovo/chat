## 实测发现和修复

1. Web 原先过滤 `externalKey=null` 的原生会话，使 Android 新建的会话无法在 Web 打开。Web 以原会话内部 ID 作为兼容 chatId，数据库查找兼容无外部键的原生 ID；保留 tenant/user/deleted 约束，显式外部键优先。从 Web 发新消息复测确认仍进入原 session/workspace。没有迁移或修改既有会话标识。
2. Web 新建会话请求期间输入框仍可编辑，初始化完成会清掉过早输入。创建期间禁用 composer，准备完成后恢复。延迟创建接口的浏览器回归覆盖此窗口。

环境失败单独记录：Android 初始 Debug JS 加载超过脚本 15 秒等待；Gboard 初始为折叠实体键盘工具栏，展开后又因拼音候选取消导致输入未提交。关闭 AVD 硬件键盘、冷启动并切换 English 后完整重跑通过，持久 AVD 配置已经恢复。Android 多行输入另测通过，composer 与键盘间距 30px。测试中出现 Metro 调试连接告警，但应用真实上传、模型回复和历史恢复均成功；此告警不计为业务验证失败。

Web 扩展控制不可用，原生 Chrome 被当前桌面操作打断；采用独立真实 Playwright 上下文。实际模型 E2E 没有替换业务响应。延迟接口回归则使用 mock，单独统计。

## 追加回归：问候在失败续跑后被误当作开发任务

用户原会话的首轮在模型初始化前失败，没有写入图 checkpoint；Web 点击“继续对话”时，服务端原先只提交通用的“继续上一轮任务”指令，未带原始问候。模型缺失任务正文，继而弹出了开发任务选项。此前三端 E2E 覆盖新消息与正常续聊，漏掉了“首轮尚未进入模型便失败，再点击继续”这条路径。

修复：数据库事务内读取当前会话最近一条非 continuation 请求，把原文与原有 ready 附件一并写入续跑的持久化输入。多次续跑仍定位原始请求，不嵌套内部指令；附件保留原 run 归属。API 续跑指令不再要求无条件检查工作进度；产品提示明确普通问候不列开发菜单、不用技术偏好替代当前意图。

验证：

- DB 63 项（包含真实隔离库集成测试）、API 136 项通过；DB / API / agent-core 类型检查及 diff 检查通过。
